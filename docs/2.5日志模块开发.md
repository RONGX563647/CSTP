## 1. 概述

### 1.1 功能简介

日志管理模块用于记录系统中所有用户和管理员的操作行为，支持日志查看、筛选、统计和清理功能。

### 1.2 功能特性

- **多维度筛选**：支持按模块、操作类型、操作人、角色、状态、时间范围、关键词等条件筛选
- **实时统计**：展示今日/本周/总日志数量，支持各模块和状态的统计
- **日志详情**：查看完整的请求信息、响应状态、耗时、IP地址等
- **日志清理**：支持按时间条件清理历史日志
- **订单日志**：在订单模块中保留了原有的 `OrderLog`，用于记录订单状态变更

## 2. 设计思路

### 2.1 双层日志架构

项目采用双层日志架构：

1. **通用操作日志 (`operation_logs`)**
   - 记录所有模块的用户操作
   - 支持灵活的查询和统计
   - 可用于安全审计

2. **业务专用日志 (`order_logs`)**
   - 订单模块专用，记录订单状态变更
   - 包含订单状态转换信息
   - 保留原有设计

### 2.2 日志记录时机

| 时机 | 说明 |
|------|------|
| 用户登录/登出 | Auth 模块自动记录 |
| 用户注册 | Auth 模块自动记录 |
| CRUD 操作 | 在 Service 中手动调用 |
| 管理操作 | 在 Controller 或 Service 中调用 |
| 系统操作 | 定时任务等自动执行的操作 |

### 2.3 角色枚举

| 角色 | 说明 |
|------|------|
| BUYER | 买家 |
| SELLER | 卖家 |
| ADMIN | 管理员 |
| SYSTEM | 系统（定时任务等） |

## 3. 数据库设计

### 3.1 operation_logs 表

```sql
CREATE TABLE operation_logs (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    module VARCHAR(50) NOT NULL COMMENT '模块：USER, PRODUCT, ORDER...',
    action VARCHAR(50) NOT NULL COMMENT '操作类型：LOGIN, CREATE...',
    operator_id BIGINT COMMENT '操作人ID',
    operator_name VARCHAR(100) COMMENT '操作人用户名',
    operator_role VARCHAR(20) COMMENT '操作人角色',
    description VARCHAR(500) COMMENT '操作描述',
    request_method VARCHAR(10) COMMENT 'HTTP方法',
    request_url VARCHAR(500) COMMENT '请求URL',
    request_params TEXT COMMENT '请求参数',
    status VARCHAR(20) COMMENT '状态：SUCCESS, FAIL',
    message VARCHAR(500) COMMENT '错误信息',
    duration BIGINT COMMENT '耗时（毫秒）',
    ip VARCHAR(50) COMMENT 'IP地址',
    user_agent VARCHAR(500) COMMENT '浏览器信息',
    biz_id BIGINT COMMENT '关联业务ID',
    biz_type VARCHAR(50) COMMENT '关联业务类型',
    create_time DATETIME COMMENT '创建时间',
    INDEX idx_operator_id (operator_id),
    INDEX idx_module (module),
    INDEX idx_action (action),
    INDEX idx_create_time (create_time),
    INDEX idx_operator_role (operator_role)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='操作日志表';
```

### 3.2 order_logs 表（原有）

```sql
CREATE TABLE order_logs (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    order_id BIGINT NOT NULL COMMENT '订单ID',
    operator_id BIGINT COMMENT '操作人ID',
    operator_role VARCHAR(20) COMMENT '操作人角色',
    action VARCHAR(50) NOT NULL COMMENT '操作类型',
    from_status VARCHAR(20) COMMENT '变更前状态',
    to_status VARCHAR(20) COMMENT '变更后状态',
    remark VARCHAR(500) COMMENT '备注',
    create_time DATETIME COMMENT '创建时间'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='订单日志表';
```

## 4. 后端实现

### 4.1 实体类

**OperationLog.java**

```java
@Entity
@Table(name = "operation_logs", indexes = {
    @Index(name = "idx_operator_id", columnList = "operatorId"),
    @Index(name = "idx_module", columnList = "module"),
    @Index(name = "idx_action", columnList = "action"),
    @Index(name = "idx_create_time", columnList = "createTime"),
    @Index(name = "idx_operator_role", columnList = "operatorRole")
})
public class OperationLog {
    // 核心字段
    private Long id;
    private String module;           // 模块
    private String action;           // 操作类型
    private Long operatorId;         // 操作人ID
    private String operatorName;     // 操作人用户名
    private OperatorRole operatorRole; // 角色
    private String description;      // 描述
    // 请求信息
    private String requestMethod;
    private String requestUrl;
    private String requestParams;
    // 响应信息
    private String status;
    private String message;
    private Long duration;
    // 客户端信息
    private String ip;
    private String userAgent;
    // 业务关联
    private Long bizId;
    private String bizType;
    private LocalDateTime createTime;
}
```

### 4.4 使用示例

在 Service 中记录操作日志：

```java
@Service
@RequiredArgsConstructor
public class ProductService {
    private final OperationLogService logService;

    public Product createProduct(Product product, User user, HttpServletRequest request) {
        // 业务逻辑
        Product saved = productRepository.save(product);

        // 记录日志
        logService.logSuccess(
            OperationLog.Module.PRODUCT.name(),
            OperationLog.ActionType.CREATE.name(),
            user.getId(),
            user.getUsername(),
            OperationLog.OperatorRole.SELLER,
            "创建商品：" + product.getTitle(),
            request,
            System.currentTimeMillis() - startTime
        );

        return saved;
    }
}
```

## 7. 使用说明

### 7.1 管理端访问

1. 登录管理端账号
2. 在左侧菜单点击「日志管理」
3. 查看日志列表和统计数据

### 7.2 筛选日志

支持以下筛选条件组合使用：

- **模块筛选**：USER、PRODUCT、ORDER 等
- **操作类型**：LOGIN、CREATE、UPDATE 等
- **操作人**：输入用户名模糊查询
- **角色**：BUYER、SELLER、ADMIN、SYSTEM
- **状态**：SUCCESS、FAIL
- **时间范围**：选择起止日期
- **关键词**：匹配描述或请求URL

### 7.3 查看详情

点击日志列表中的「详情」按钮，可查看：
- 基本信息（模块、操作、状态）
- 操作人信息（ID、用户名、角色）
- 请求信息（方法、URL、参数）
- 响应信息（状态、耗时、错误信息）
- 客户端信息（IP、User-Agent）
- 操作时间

### 7.4 清理旧日志

1. 点击「清理旧日志」按钮
2. 选择清理日期（此日期之前的日志将被删除）
3. 确认执行

> ⚠️ 警告：清理操作不可逆，请谨慎操作！

## 8. 扩展功能

### 8.1 AOP 自动日志记录

可以扩展 LogAspect 切面，自动记录 Controller 层的操作：

```java
@Aspect
@Component
public class OperLogAspect {

    @Around("@annotation(operLog)")
    public Object around(ProceedingJoinPoint joinPoint, OperLog operLog) throws Throwable {
        // 获取操作信息
        String module = operLog.module();
        String action = operLog.action();

        // 执行方法
        long start = System.currentTimeMillis();
        Object result = joinPoint.proceed();
        long duration = System.currentTimeMillis() - start;

        // 记录日志
        // ...

        return result;
    }
}
```

使用注解：

```java
@OperLog(module = "USER", action = "UPDATE")
public ApiResponse updateUser(Long id, UserUpdateRequest request) {
    // ...
}
```

### 8.2 异步日志记录

高并发场景下，可使用异步方式记录日志：

```java
@Async
public void logAsync(OperationLog log) {
    operationLogRepository.save(log);
}
```

### 8.3 日志告警

针对 FAIL 状态的日志，可以配置告警：

```java
@EventListener
public void onLogCreated(OperationLog log) {
    if ("FAIL".equals(log.getStatus())) {
        // 发送告警通知
        alertService.sendAlert("操作失败: " + log.getDescription());
    }
}
```

### 8.4 日志归档

定期将历史日志归档到冷存储：

```java
@Scheduled(cron = "0 0 2 * * ?")  // 每天凌晨2点
public void archiveOldLogs() {
    LocalDateTime archiveDate = LocalDateTime.now().minusDays(90);
    // 归档90天前的日志
    logArchiveService.archive(archiveDate);
}
```
