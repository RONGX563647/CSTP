## 一、需求分析

### 1.1 功能概述

用户签到体系是 AiSale 校园二手交易平台的用户留存与活跃功能，鼓励用户每日登录使用平台，通过连续签到获取递增积分奖励，提升用户粘性。

### 1.2 功能需求

| 需求项 | 说明 | 优先级 |
|--------|------|--------|
| 每日签到 | 用户每天可签到一次，不可重复签到 | P0 |
| 连续签到 | 自动计算连续签到天数，断签后重新计数 | P0 |
| 阶梯奖励 | 连续签到天数越多，每日获得积分越多 | P0 |
| 签到状态 | 查看今日是否已签到、连续天数、累计天数 | P0 |
| 签到日历 | 月度签到记录可视化展示 | P1 |
| 近期记录 | 近7天/30天签到情况展示 | P1 |

### 1.3 非功能需求

| 需求 | 说明 |
|------|------|
| 并发安全 | 同一用户同一日期只能签到一次（数据库唯一索引保障） |
| 时区一致 | 签到日期统一使用服务器本地日期（`LocalDate.now()`） |
| 性能 | 签到接口响应时间 < 200ms |

## 二、数据库设计

### 2.1 check_ins 表

```sql
CREATE TABLE check_ins (
    id          BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_id     BIGINT       NOT NULL,
    check_in_date DATE       NOT NULL,
    continuous_days INT      NOT NULL DEFAULT 1,
    reward_points   INT      DEFAULT 0,
    created_at  TIMESTAMP    NOT NULL,

    UNIQUE INDEX idx_checkin_user_date (user_id, check_in_date)
);
```

### 2.2 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT | 自增主键 |
| `user_id` | BIGINT | 用户 ID（关联 users 表） |
| `check_in_date` | DATE | 签到日期（精确到天） |
| `continuous_days` | INT | 截至当天的连续签到天数 |
| `reward_points` | INT | 本次签到获得的积分 |
| `created_at` | TIMESTAMP | 签到时间戳 |

### 2.3 索引设计

| 索引 | 类型 | 说明 |
|------|------|------|
| `PRIMARY` | 主键 | id 自增主键 |
| `idx_checkin_user_date` | 唯一索引 | `(user_id, check_in_date)` 防止同日重复签到 |

> **设计决策：** 使用唯一索引而非应用层锁来防止重复签到，因为数据库约束是最可靠的幂等性保障。即使并发请求同时到达，数据库也会拒绝第二次插入。

## 三、后端实现

### 3.1 Entity 实体层

**文件：** `backend/src/main/java/com/aisale/backend/entity/CheckIn.java`

```java
@Data
@Entity
@Table(name = "check_ins", indexes = {
    @Index(name = "idx_checkin_user_date", columnList = "user_id, check_in_date", unique = true)
})
public class CheckIn {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(name = "user_id", nullable = false)
    private Long userId;

    @Column(name = "check_in_date", nullable = false)
    private LocalDate checkInDate;

    @Column(name = "continuous_days", nullable = false)
    private Integer continuousDays = 1;

    @Column(name = "reward_points")
    private Integer rewardPoints = 0;

    private LocalDateTime createdAt;

    @PrePersist
    protected void onCreate() {
        createdAt = LocalDateTime.now();
    }
}
```

**设计要点：**

| 决策 | 原因 |
|------|------|
| `userId` 用 Long 而非 User 关联 | 签到记录高频写入，简单外键 ID 减少 JOIN 开销 |
| `checkInDate` 用 LocalDate | 只需日期精度，避免时区问题 |
| `continuousDays` 冗余存储 | 避免每次查询都要回溯计算连续天数 |
| 唯一索引 `user_id + check_in_date` | 数据库层面保证幂等性 |

### 3.4 Service 业务逻辑层

**文件：** `backend/src/main/java/com/aisale/backend/service/CheckInService.java`

#### 3.4.1 签到逻辑（核心）

```java
@Transactional
public CheckInResponse checkIn(String username) {
    User user = userRepository.findByUsername(username)
            .orElseThrow(() -> new NotFoundException("用户不存在"));

    LocalDate today = LocalDate.now();

    // 1. 幂等校验：今日是否已签到
    checkInRepository.findByUserIdAndCheckInDate(user.getId(), today)
            .ifPresent(existing -> {
                throw new ConflictException(ErrorCode.CHECK_IN_ALREADY_DONE);
            });

    // 2. 计算连续天数
    int continuousDays = calculateContinuousDays(user.getId(), today);

    // 3. 计算奖励积分
    int rewardPoints = calculateRewardPoints(continuousDays);

    // 4. 创建记录
    CheckIn checkIn = new CheckIn();
    checkIn.setUserId(user.getId());
    checkIn.setCheckInDate(today);
    checkIn.setContinuousDays(continuousDays);
    checkIn.setRewardPoints(rewardPoints);
    checkIn = checkInRepository.save(checkIn);

    // 5. 返回
    long totalDays = checkInRepository.countByUserId(user.getId());
    return CheckInResponse.fromEntity(checkIn, true, (int) totalDays);
}
```

#### 3.4.2 连续天数计算

```java
private int calculateContinuousDays(Long userId, LocalDate today) {
    LocalDate yesterday = today.minusDays(1);
    return checkInRepository.findByUserIdAndCheckInDate(userId, yesterday)
            .map(yesterdayCheckIn -> yesterdayCheckIn.getContinuousDays() + 1)
            .orElse(1);
}
```

**逻辑说明：** 查询昨天是否有签到记录。如果有，在昨天的连续天数基础上 +1；否则从 1 开始。这样无需回溯历史，只需一次查询即可完成计算。

#### 3.4.3 阶梯奖励规则

```java
private int calculateRewardPoints(int continuousDays) {
    if (continuousDays >= 7) return 20;   // 连续7天及以上：20分/天
    if (continuousDays >= 2) return 10;   // 连续2-6天：10分/天
    return 5;                              // 连续1天：5分
}
```

| 连续天数 | 每日奖励 | 说明 |
|----------|----------|------|
| 1 天 | 5 积分 | 首日签到 |
| 2-6 天 | 10 积分 | 持续签到奖励 |
| 7 天+ | 20 积分 | 长期坚持奖励 |

#### 3.4.4 签到状态查询

```java
@Transactional(readOnly = true)
public CheckInStatusResponse getCheckInStatus(String username) {
    // 1. 今日是否已签到
    boolean todayCheckedIn = checkInRepository
        .findByUserIdAndCheckInDate(user.getId(), today).isPresent();

    // 2. 最近一次签到 → 获取连续天数
    CheckIn lastCheckIn = checkInRepository
        .findTopByUserIdOrderByCheckInDateDesc(user.getId()).orElse(null);

    // 3. 连续天数有效性判断（今天已签到 或 昨天签到了才算连续）
    if (lastCheckIn != null) {
        if (todayCheckedIn || lastCheckInDate.equals(today.minusDays(1))) {
            continuousDays = lastCheckIn.getContinuousDays();
        }
    }

    // 4. 近30天签到日期（前端日历/7天展示用）
    List<LocalDate> recentDates = checkInRepository
        .findByUserIdAndCheckInDateBetweenOrderByCheckInDateAsc(...)
        .stream().map(CheckIn::getCheckInDate).toList();
}
```

## 五、关键技术决策

### 5.1 幂等性保障

**方案对比：**

| 方案 | 优点 | 缺点 |
|------|------|------|
| 数据库唯一索引 | 最可靠，并发安全 | 插入失败抛异常 |
| 应用层 Redis 锁 | 性能好 | 引入新依赖，需处理锁超时 |
| 应用层查询判断 | 简单 | 并发下不可靠 |

**选择：数据库唯一索引 + 应用层查询预检**

- 应用层先查询是否已签到（快速返回，避免异常处理）
- 数据库唯一索引作为兜底保障

### 5.2 连续天数计算

**方案：冗余存储 `continuous_days` 字段**

每次签到时，查询昨天的记录获取其 `continuous_days` 值 +1，无需回溯全量历史。断签后自然从 1 开始。

**为什么不实时计算？**
- 实时计算需要查询全部签到记录并按日期排序，判断相邻日期是否连续
- 时间复杂度 O(n)，签到天数多时性能差
- 冗余存储只需 1 次查询，O(1) 复杂度

### 5.3 时区处理

统一使用 `LocalDate.now()`（JVM 默认时区），数据库存储 DATE 类型。避免使用 `LocalDateTime` 带来的时区转换问题。
