# 3.4 用户信誉模块开发

## 一、需求分析

### 1.1 功能需求

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 信誉账户 | 每个用户一个信誉账户，记录信誉分、评价统计、等级信息 | P0 |
| 信誉计算 | 根据订单评价自动计算信誉分变化 | P0 |
| 信誉等级 | 根据平均评分和评价数量自动计算信誉等级（1-5级） | P0 |
| 信誉流水 | 记录每笔信誉变动，支持分页查询 | P0 |
| 管理员调整 | 管理员可手动调整用户信誉分并填写原因 | P0 |
| 前端展示 | 信誉概览卡片、评价统计、等级说明、信誉明细列表 | P0 |
| 公开查询 | 支持查看其他用户的公开信誉信息 | P1 |

### 1.2 非功能需求

- 信誉变动必须事务性，账户余额与流水记录强一致
- 信誉分不能为负数（最小为0）
- 信誉流水不可篡改，仅追加
- 接口响应时间 < 200ms

| total_reviews | INT | NOT NULL, DEFAULT 0 | 收到的评价总数 |

| neutral_reviews | INT | NOT NULL, DEFAULT 0 | 中评数（3分） |
| bad_reviews | INT | NOT NULL, DEFAULT 0 | 差评数（1-2分） |
| avg_rating | DECIMAL(3,2) | DEFAULT 0.0 | 平均评分（1-5） |
| level | INT | NOT NULL, DEFAULT 3 | 信誉等级（1-5级） |
| created_at | TIMESTAMP | | 创建时间 |
| updated_at | TIMESTAMP | | 更新时间 |

**索引**：`idx_reputation_account_user` (user_id) UNIQUE

### 2.2 reputation_records（信誉流水表）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | BIGINT | PK, AUTO_INCREMENT | 主键 |
| user_id | BIGINT | NOT NULL | 用户ID |
| review_id | BIGINT | NULL | 关联评价ID |
| record_type | VARCHAR(30) | NOT NULL | 记录类型 |
| score_change | INT | NOT NULL | 信誉变化（正/负） |
| balance_after | INT | NOT NULL | 变化后信誉分快照 |

| created_at | TIMESTAMP | NOT NULL | 创建时间 |

**索引**：
- `idx_reputation_record_user` (user_id)
- `idx_reputation_record_time` (created_at)

### 2.3 记录类型枚举

## 三、信誉计算规则

### 3.1 评分对应信誉变化

| 评分 | 信誉变化 | 说明 |
|------|----------|------|
| 5分（好评） | +10 | 最高好评奖励 |
| 4分（好评） | +5 | 普通好评奖励 |
| 3分（中评） | +0 | 中评不影响信誉 |
| 2分（差评） | -5 | 差评扣减信誉 |
| 1分（极差） | -10 | 极差评价扣减更多 |

### 3.2 信誉等级计算

| 等级 | 名称 | 条件 | 图标 |
|------|------|------|------|
| 5级 | 优秀 | avgRating >= 4.8 且 totalReviews >= 50 | 🌟🌟🌟🌟🌟 |
| 4级 | 良好 | avgRating >= 4.5 且 totalReviews >= 20 | 🌟🌟🌟🌟 |
| 3级 | 一般 | avgRating >= 4.0 或 无评价（默认） | 🌟🌟🌟 |
| 2级 | 较差 | avgRating < 4.0 | 🌟🌟 |
| 1级 | 极差 | avgRating < 3.0 | 🌟 |

## 四、后端实现

### 4.1 Entity 层

```
ReputationAccount.java  — 信誉账户实体（含 ReputationLevel 枚举）
ReputationRecord.java   — 信誉流水实体（含 RecordType 枚举）
```

关键设计：
- ReputationAccount 的 `user_id` 设置 UNIQUE 约束，确保一户一账户
- ReputationRecord 的 `score_change` 字段使用正负数表示增加/扣减
- `balance_after` 记录变动后余额快照，便于对账
- 内嵌 `ReputationLevel` 枚举提供等级计算逻辑

### 4.2 Repository 层

```
ReputationAccountRepository.java  — 按用户ID查询账户、检查账户存在
ReputationRecordRepository.java   — 分页查询流水、按类型筛选、统计次数
```

### 4.3 DTO 层

| DTO | 用途 |
|-----|------|
| ReputationAccountResponse | 信誉账户概览（含好评率、等级名称、图标） |
| ReputationRecordResponse | 信誉流水记录响应 |
| AdminReputationAdjustRequest | 管理员调整信誉请求（含分数范围校验） |

### 4.4 Service 层

**ReputationService** 核心方法：

```java
// 获取或创建信誉账户（懒创建，初始100分）
ReputationAccount getOrCreateAccount(Long userId)

// 获取账户概览
ReputationAccountResponse getAccountOverview(String username)

// 获取指定用户公开信誉信息
ReputationAccountResponse getAccountByUserId(Long userId)

// 获取信誉流水（分页）
Page<ReputationRecordResponse> getRecords(String username, int page, int size)

// 根据评价更新信誉（核心方法）
ReputationRecord updateReputationFromReview(OrderReview review)

// 管理员调整信誉
ReputationRecordResponse adminAdjust(Long targetUserId, AdminReputationAdjustRequest request)
```

**与订单评价模块集成**：OrderReviewService 创建评价后调用 `reputationService.updateReputationFromReview()` 自动更新信誉。

### 4.5 Controller 层

**用户端** (`/api/user/reputation`)：

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | / | 获取我的信誉概览 |
| GET | /records?page=&size= | 获取信誉流水 |
| GET | /public/{userId} | 获取指定用户公开信誉信息 |

**管理端** (`/api/admin/users`)：

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /{id}/reputation | 获取用户信誉详情 |
| POST | /{id}/reputation/adjust | 调整用户信誉分 |

## 五、事务一致性保障

### 5.1 评价+信誉事务

`OrderReviewService.createReview()` 方法标注 `@Transactional`，评价创建和信誉更新在同一事务中：

```
1. 校验订单状态和评价权限
2. 创建评价记录
3. 调用 reputationService.updateReputationFromReview()
   - 获取/创建信誉账户
   - 计算信誉变化（根据评分）
   - 更新评价统计（好评/中评/差评数）
   - 更新信誉分（不能为负）
   - 计算平均评分
   - 计算信誉等级
   - 创建信誉流水记录
4. 检查双方是否都已评价，更新订单状态
5. 事务提交（任一步骤失败全部回滚）
```

### 5.2 信誉分下限保护

```java
// updateReputationFromReview 方法中的下限保护
int newScore = account.getTotalScore() + scoreChange;
account.setTotalScore(Math.max(0, newScore)); // 信誉分不能为负
```
